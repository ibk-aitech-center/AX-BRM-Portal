# AX-BRM 최초 배포 지시서 (시스템 담당자용)

반입 파일 2개: `ai-brm-base.tar`(베이스 이미지) · `dist.zip`(Dockerfile · start.sh · nginx.conf · build.sh · ui.tar.gz · app.tar.gz · create-db.sql · init-db.sql · k8s/)
(선택) `CHECKSUMS.md5` 가 함께 왔으면 `md5sum -c CHECKSUMS.md5` 로 전송 손상 여부만 확인 — 없어도 배포에는 영향 없음

> 서버는 Spring Boot 가 아니라 **Node(Express)** 입니다. 가이드의 app.jar 자리에 `app.tar.gz`(코드 + 운영 node_modules)가 들어가고,
> 베이스 이미지는 nginx + **node** 입니다. 빌드에 npm·인터넷이 필요 없습니다(`--network none` 으로 빌드 가능).

> **이미지는 1개**(`ai-brm:<ver>`)입니다. 컨테이너 하나에서 `/app/start.sh` 가 nginx(80, 화면 + `/api/` 프록시)와 Node API(3000)를 함께 띄웁니다.
> 플랫폼 배포 템플릿이 컨테이너 args 로 `/app/start.sh` 를 넘겨도 되고, 비워 두면 이미지 CMD 가 같은 스크립트를 부릅니다. 외부에 여는 포트는 **80** 하나입니다.

## 1. DB 준비 (PostgreSQL, DB 담당자)
1. `create-db.sql` 의 `<비밀번호>` 를 정한 값으로 바꾼 뒤 **postgres 슈퍼유저**로 실행
   `psql -U postgres -f create-db.sql`  → 계정 `aibrm`, DB `aibrm` 생성
2. **aibrm 계정으로** 테이블 생성 (postgres 로 실행하면 안 됨 — 소유권 문제)
   `psql -U aibrm -d aibrm -f init-db.sql`
3. 1에서 정한 비밀번호는 `DATABASE_URL` 에만 넣는다 (`k8s/10-secret.yaml` 또는 플랫폼의 env 설정)

## 2. 이미지 빌드
```
docker load < ai-brm-base.tar          # ai-brm-base:1.0
unzip dist.zip -d ai-brm && cd ai-brm
sh build.sh 1.4                        # → ai-brm:1.4   (= docker build --network none -t ai-brm:1.4 .  — dist.zip 루트의 Dockerfile 로 직접 빌드해도 같다)
```
사내 레지스트리에 push 해서 k8s 가 당길 수 있게 한다 (예: `<registry>/ai-brm:1.4`).

## 3. 배포
### 3-A. 플랫폼 배포 템플릿으로 띄우는 경우 (Deployment 를 플랫폼이 만들어 줄 때)
| 항목 | 값 |
|---|---|
| 이미지 | `<registry>/ai-brm:<ver>` |
| 컨테이너 포트 | **80** |
| 기동 명령(args) | 비워 두거나 `/app/start.sh` |
| 필수 env | `DATABASE_URL=postgres://aibrm:<pw>@<PG host>:5432/aibrm`, `SSO_JWT_SIGN=<AI 포탈 운영팀 수령값, 32자 이상>` (짧으면 기동 거부) |
| 선택 env | `APP_URL=https://<host>`(알림 링크), `HR_DB_HOST/PORT/NAME/USER/PASSWORD`(인사 미러), `ALARM_URL`·`ALARM_SRV_CODE`(IBK톡), `UPLOAD_MAX_MB`(기본 20) |
| 볼륨 | PVC → `/app/data` (첨부 파일 — 없으면 재배포 때 첨부가 사라짐). RWO 면 replicas 1 |
| 프로브 | startup·readiness `GET /api/health` 포트 80 (DB 응답 + 첨부 폴더 쓰기 가능일 때 200, 아니면 503), liveness TCP 80 |
| Ingress | `https://<host>/` 전체(`/api/` 포함) → 서비스 포트 80. 업로드 한도 `proxy-body-size 32m`, read timeout 120s |

### 3-B. 동봉한 `k8s/` 매니페스트로 띄우는 경우 (상세는 `k8s/README.md`)
① 자리표시자 채우기
   - `<registry>` `<host>` 일괄 치환: `sed -i 's#<registry>#<사내 레지스트리>/aibrm#g; s#<host>#<서비스 host>#g' k8s/*.yaml`
   - `k8s/10-secret.yaml`: `DATABASE_URL` 의 `<비밀번호>`(1-①에서 정한 값)·`<PG host>`, `SSO_JWT_SIGN`(**32자 이상**)
   - `k8s/11-configmap.yaml`: `APP_URL`(알림 링크), 인사 미러 `HR_DB_*`·IBK톡 `ALARM_*` 는 있으면 채우고 없으면 "" 그대로
   - `k8s/30-ingress.yaml`: ingressClassName · TLS 는 사내 표준대로
② 적용: `kubectl apply -n <ns> -f k8s/` (파일명 순서 = 적용 순서: Secret·ConfigMap → PVC → Deployment → Service → Ingress)

### 확인 (공통)
- `kubectl -n <ns> logs deploy/ai-brm`(또는 해당 파드) 에 `[db] pg ready` 와 `[server] http://localhost:3000 (production)`
- `https://<host>/` 200, `https://<host>/api/health` 200 (`"db":{"ok":true}`, `"uploads":{"ok":true}`)
- 기동 실패 시 로그 첫 줄이 원인이다: `DATABASE_URL 이 비어 있어요` / `SSO_JWT_SIGN 이 없거나 32자 미만` → env 누락. `Cannot find module '/app/start.sh'` 는 1.2 묶음부터 나오지 않는다.

## 4. 배포 후 1회 작업
1. AI 포탈 운영팀에 SSO 리디렉트 주소 등록 요청: `https://<host>/?token=`
2. `HR_DB_*` 를 넣었다면 파드에서 `npm run hr:sync` 1회 (또는 관리 화면 "동기화") → 직책·BRM 권한 채움
3. 시스템 관리자(024498·044692)로 로그인해 관리 화면에서 담당자 확인

## 이후 재배포
새 `dist.zip` 만 반입 → 2 의 `sh build.sh <새 버전>` → 레지스트리 push → 이미지 태그만 갱신 (`kubectl -n <ns> set image deploy/ai-brm app=<registry>/ai-brm:<ver>` 또는 플랫폼에서 태그 변경). `ai-brm-base.tar` 는 베이스가 바뀔 때만 다시 반입.
DB 스키마 변경은 API 기동 시 자동 반영(`ALTER TABLE` 추가형만, 데이터 삭제 없음), PVC 는 그대로 둔다.
