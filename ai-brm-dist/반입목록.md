## 반입 파일 (가이드 방식: base 이미지 + dist.zip, 내부망에서 빌드)

| 파일 | 내용 | 내부망에서 |
|---|---|---|
| `ai-brm-base.tar` (56 MB) | 베이스 이미지 `ai-brm-base:1.0` = node:22-alpine + nginx + Asia/Seoul — 최초 1회, 베이스가 바뀔 때만 재반입 | `docker load < ai-brm-base.tar` |
| `dist.zip` (25 MB) | 아래 묶음. **루트의 `Dockerfile` 로 이미지 1개**(`ai-brm:<ver>`)를 만든다 | `unzip dist.zip && sh build.sh <ver>` (= `docker build --network none -t ai-brm:<ver> .`) |

`dist.zip` 내용:
| 파일 | 내용 |
|---|---|
| `Dockerfile` | 단일 이미지: nginx(80) + Node API(3000). `ADD` 로 아래 두 tar 를 풀고 npm 은 부르지 않는다 — **인터넷·npm 미러 불필요** |
| `start.sh` | 컨테이너 기동 스크립트(`/app/start.sh`) — nginx 와 node 를 함께 띄우고, 하나라도 죽으면 컨테이너를 내린다. 이미지 CMD 이자 플랫폼 템플릿 args 값 |
| `nginx.conf` | 화면 서빙 + `/api/` → `127.0.0.1:3000` 프록시, 업로드 한도 32m |
| `build.sh` | `docker build --network none -t ai-brm:<ver> .` 를 사전 점검과 함께 실행 |
| `ui.tar.gz` | 빌드된 화면(index.html · assets) — nginx html 루트에 그대로 풀리는 구조 |
| `app.tar.gz` | 가이드의 app.jar 대응 — package*.json · **운영 node_modules(express·pg·mysql2)** · server/ · shared/. 그대로 `node server/index.js` 로 기동 가능 |
| `create-db.sql` | 계정 `aibrm` + DB `aibrm` 생성 (postgres 슈퍼유저로 1회, `<비밀번호>` 는 DB 담당자가 정함) |
| `init-db.sql` | 테이블 생성 + `aibrm` 계정 권한 — **aibrm 계정으로 실행** (postgres 로 실행하면 소유권 문제로 마이그레이션 실패) |
| `k8s/` | 매니페스트 6개(Secret · ConfigMap · PVC · Deployment · Service · Ingress) + README. 플랫폼 템플릿으로 띄우면 참고용(필요 값은 배포지시서 3-A) |

기동 시 컨테이너 환경변수(필수): `DATABASE_URL=postgres://aibrm:<pw>@<host>:5432/aibrm`, `SSO_JWT_SIGN=<포탈 운영팀 수령값, 32자 이상>`.
선택: `HR_DB_*`(인사 미러), `ALARM_URL`/`ALARM_SRV_CODE`(IBK톡), `APP_URL`. 첨부는 `/app/data` 에 PVC 마운트. 외부 포트 80.

개발망에서 다시 만들기: `sh scripts/make-dist.sh` (화면 빌드 → app.tar.gz → dist.zip → CHECKSUMS.md5).

## 이전 빌드(1.2, 2026-09-07)에 들어간 변경
- **역할 일괄 변경**: 담당자 관리에서 팀·부서명으로 검색 → 체크(전체 선택) → 역할 고르고 "일괄 변경". 미접속 직원은 등록하면서 부여, 자기 자신의 관리자 권한은 건너뜀. 한 트랜잭션(중간 실패 시 아무도 안 바뀜), 최대 200명
- **운영 번들 수정(중요)**: 이전 묶음은 `.env` 의 `NODE_ENV=development` 가 빌드에 스며들어 Vue 개발 런타임이 포함되고 로그아웃 버튼이 운영에 노출됐음. 이번 묶음부터 production 으로 고정(번들 228KB → 114KB). 로그아웃 버튼은 접속 호스트가 localhost 일 때만 표시
- **관리자 전용 접수 삭제**: 접수함 상세 상단(이력 버튼 옆) "접수 삭제" 버튼(관리자에게만 보임). 접수번호를 그대로 입력해야 삭제되며 의견·이력·첨부(파일)·대화까지 함께 영구 삭제. 요청자·AX-BRM 은 신청된 건을 지울 수 없음(403). 서버 로그에 삭제 기록
- **접수함 상세 재구성**: 요청자 답변 전체를 첫 화면에, 자동 판정은 접힌 참고 카드로. "모르겠어요" 답변 표시
- nginx: index.html 을 캐시하지 않음(새 배포가 바로 반영되도록)
- **역할 부여가 로그인 전에도 됨**: HR 미러링 때 **미러의 전 직원**이 users 에 미리 등록됨(1094 소속은 AX-BRM, 나머지는 일반 사용자) → 담당자 관리에서 검색해 로그인 전에 어떤 역할이든 부여 가능, 첫 로그인부터 적용. 첫 로그인 역할도 미러 규칙으로 결정(동기화 전 신규·전입 직원 대비)

- **포탈 자동 리디렉트는 토큰이 없을 때만**: 토큰이 있는데 서버가 거절하면 폐기만 하고 "다시 로그인이 필요해요" 화면에서 사용자가 "포탈로 이동"을 눌러야 이동(포탈↔앱 루프 방지)
